# AI Work design
Replace only the Sync Hub exam tab with AI Work; retain standalone QBuilder. User selects Google Docs, chats a task, reads and edits task text, regenerates the proposal, reviews before/after highlights and selects changes, then explicitly chooses Proceed or Cancel. No writes before Proceed. Cancel discards proposal; original unchanged. Read through Docs API with drive.file; access token stays in browser and never goes to the AI endpoint. Document content is sent to configured AI provider only on explicit Generate.
Initial version supports text edits in body paragraphs including tables and multiple tabs; blocks containing equations/images/unsupported elements are read-only and never deleted. Native Docs rendering remains in iframe; diff is a separate local preview, not a live-doc highlight. Preserve unrelated text and formatting through minimal text-range patches. Verify document identity, original text, current revision and canEdit before atomic batchUpdate. Stale tasks/documents cannot apply. Scope selection allows all supported paragraphs or a specific paragraph. Non-owned read-only docs require existing copy flow. Keep a session history of actions, prevent duplicate submissions, report uncertain write results without automatic retry. Undo uses inverse patches only against the exact post-write revision; conflict stops undo.
No new packages, production deployment, automatic real-document writes or unrelated refactors. Keep existing dirty checkout and changes as explicitly requested current-page work.
